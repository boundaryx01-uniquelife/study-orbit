# STUDY ORBIT v0.7.5 — 페이지 진행률과 수동 시간 기록

v0.7.5에서는 모든 PWA 버튼에 공통 한 줄 표시 규칙을 적용했습니다. 모바일 폭에서는 버튼 글자 크기와 좌우 간격을 줄이고, 버튼 그룹 간격을 조정해 텍스트가 버튼 안에서 줄바꿈되지 않습니다.

v0.7.6에서는 문제집 학습 로그마다 `수정`과 `삭제`를 제공합니다. 변경·삭제 시 책의 누적 풀이·오답·시간·페이지를 로그 기준으로 다시 계산하며, v0.7 이전에 로그 없이 저장된 기존 누적값도 보존합니다. 완주 서고의 학습 로그에서도 동일하게 수정할 수 있습니다.

기존 DB는 `20260917_orbit_v073_edit_logs.sql`을 v0.7.2 마이그레이션 다음에 실행합니다.

v0.7.4에서는 Supabase JWT가 만료되기 직전에 refresh token으로 세션을 자동 갱신합니다. 저장 요청 중 401이 발생해도 한 번만 갱신 후 재시도하며, refresh token까지 만료된 경우에만 다시 로그인을 안내합니다.

v0.7.3에서는 타이머를 사용할 수 없는 경우를 위해 학습 화면에 **시간 직접 기록**을 추가했습니다. 날짜와 시작·종료 시간대를 입력하면 분을 자동 계산하고, 시간(분)만 입력하는 방식도 지원합니다. 문제집을 연결하면 페이지·문항·정답률 통계에 기존 방식으로 누적됩니다.

## 적용 순서

1. 기존 PC의 STUDY ORBIT 저장소에서 `git status`로 변경사항을 확인하고 `git pull --ff-only`를 실행합니다. 보관 중인 stash는 그대로 둡니다.
2. Supabase Dashboard → SQL Editor에서 `supabase/migrations/20260915_orbit_v072_pages.sql` 전체를 실행합니다. v0.7.0 core loop SQL을 아직 적용하지 않았다면 `20260915_orbit_v070_core_loop.sql`부터 실행합니다. 신규 DB는 최신 `supabase/schema.sql`만 실행합니다.
3. `npm install` 후 `npm run dev`를 실행하고 `http://localhost:8000`을 엽니다. 기존 `.env`의 Kakao/Supabase 설정을 그대로 사용합니다.
4. 배포된 PWA는 모든 창을 닫고 다시 열어 새 버전을 받습니다. 설치 아이콘이 계속 예전 모습이면 홈 화면 바로가기를 제거하고 다시 설치합니다. 저장된 학습 기록은 Supabase에 유지됩니다.

SQL은 자동 배포되지 않습니다. 이번 작업에서는 운영 Supabase SQL을 실행하지 않았습니다. 연결된 운영 DB 인증정보 없이 임시 PostgreSQL과 모의 API로 검증했습니다.

## 책 등록과 정보 수정

- 모든 책에 전체 페이지 수를 선택 입력할 수 있습니다. 전체 문항수도 선택입니다. 미입력 페이지는 NULL, 기존 문항수 0은 알 수 없음을 뜻합니다.
- API가 명시적인 숫자를 제공하면 등록 화면에 자동 입력하고 저장합니다. 페이지는 `total_pages`, `page_count`, `pageCount`, `pages`, 문항수는 `total_problems`, `problem_count`, `problemCount`, `question_count`를 정규화합니다. 소개문에서 숫자를 추정하지 않습니다.
- **현재 Kakao 도서 검색 API에는 페이지수와 문항수 필드가 없습니다.** 따라서 현 공급자 응답에서는 직접 입력하게 됩니다. 다른 API 보강 조회나 추가 키는 도입하지 않았습니다. [Kakao 공식 응답 명세](https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-book)
- 기존 책과 완주한 책도 ‘책 정보 수정’에서 페이지수·문항수를 수정할 수 있습니다.

## 기록 의미

- ‘학습한 페이지 수 누적’: 기존 누적 페이지에 더합니다. 20쪽 + 10쪽 = 30쪽.
- ‘현재 도달 페이지’: 기존 값과 입력값 중 큰 값을 사용합니다. 30쪽에서 50쪽 입력 → 50쪽, 다시 20쪽 입력 → 50쪽 유지.
- 현재 페이지는 기록 날짜와 관계없이 지금까지 도달한 최대 진도를 뜻합니다. 날짜는 회고용 기록일입니다.
- 복습은 페이지 입력을 비워 두고 시간·풀이·오답만 기록합니다. 같은 페이지를 중복 누적하면 고유 페이지 수를 측정할 수 없습니다.
- 전체 페이지 수를 넘는 진도는 저장하지 않습니다. 전체 페이지를 모르면 쪽수만 누적하고 분모 입력 후 진행률을 표시합니다.
- 페이지 진행률 = 누적 페이지 / 전체 페이지. 기존 문항 진행률도 유지하며 반복 풀이 때문에 100%를 넘는 경우 표시만 100%로 제한합니다.
- 정답률 = (누적 풀이 − 누적 오답) / 누적 풀이 × 100, 오답률 = 누적 오답 / 누적 풀이 × 100. 전체 문항수는 정확도 분모가 아닙니다.
- 전체 문항수가 있고 유효한 풀이가 있을 때 비율을 표시합니다. 풀이 0이거나 기존 오답이 풀이보다 많은 데이터는 비율을 표시하지 않습니다. 기존 데이터를 임의로 수정하지 않습니다.

## 데이터 보존

- 기존 테이블과 RLS 정책, 누적 풀이·오답·시간, 기록관, 기억문제는 유지합니다.
- `books.total_pages`, `books.completed_pages`와 로그의 `pages_added`, `current_page`, `request_id`만 추가합니다. 과거 기록의 페이지는 추정하지 않습니다.
- `record_book_progress`는 호출자 권한과 RLS를 사용하며 책 소유자를 확인합니다. 책 행 잠금으로 누적 갱신을 순서대로 처리합니다.
- 타이머 세션·학습 로그·책 누적치를 같은 트랜잭션에서 저장합니다. 요청 ID가 같은 재시도는 중복 기록하지 않습니다.
- SQL 적용 전 새 기록 저장은 오류 안내 후 중단됩니다. 기존 기록은 계속 조회할 수 있습니다.

## PWA

- 실제 배포 폴더 `public`에 manifest, SVG favicon, 192/512 PNG, 512 maskable PNG, Apple 180 PNG와 서비스 워커를 연결했습니다.
- 기존 ORBIT의 남색 배경, 다색 행성, 흰 궤도, 분홍 위성을 재사용했습니다. 설치 아이콘의 주요 요소는 maskable 안전 영역 안에 있습니다.
- 공개 화면 파일만 캐시합니다. 로그인·설정·Supabase 기록은 캐시하지 않으며 기록 저장에는 인터넷이 필요합니다.
- 아이콘 재생성: Pillow 설치 환경에서 `python scripts/generate-icons.py`.

## 검증

- `npm test`: API 숫자 정규화, 진행률·정답률 계산, 실제 PostgreSQL 엔진(PGlite)의 마이그레이션 재실행·기존 기록 보존·재시도·입력 검증·사용자 격리.
- `npm run build`: 배포 파일 존재 확인.
- 모의 API를 연결한 Edge 브라우저에서 390px 모바일/1365px 데스크톱, 학습 기록, 책 정보 수정, 타이머 저장, 기록관 기억문제, 자동 수치 입력과 PNG 응답 확인.
- 운영 Supabase 연결, 실제 Kakao 검색, 실제 휴대폰 홈 화면 설치는 사용 환경에서 최종 확인해야 합니다.
